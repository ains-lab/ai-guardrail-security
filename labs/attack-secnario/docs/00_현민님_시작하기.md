# 00. 현민님 시작하기 (Step 2 담당)

이 폴더는 "사내 업무 비서(RAG + 도구 5개)"를 일부러 취약하게 만들고, 공격 시나리오를 자동으로 실행·채점하는 실습 랩이다.
현민님은 **Step 2: 취약점 점검(데이터 접근 · Tool 실행)** 을 맡는다. 점검 결과표가 서진님(Step 4, Rail 구현)의 입력이 된다.

## 읽는 순서 (총 30분 정도)

1. `README.md` — 구조, 실행법, **"꼭 알아둘 것"** (mock 수치를 성과로 오해하지 말 것)
2. `docs/02_Step2_현민_인수인계.md` — 할 일, 점검 체크리스트, 산출물 형식 ← **이 문서가 본 작업 지시서**
3. `docs/01_시나리오_설계서.md` — 시나리오 23+8건 목록. **3절(심어둔 약점 W1~W11)은 점검을 끝낸 뒤 대조용으로 연다**
4. 필요할 때만: `docs/04_현황_및_남은일.md`(현황·한계), `docs/05_Udemy_Step1_대응표.md`(Udemy 근거)
## 5분 세팅 확인

```powershell
cd fc-ai-guardrail-lab
python run_scenarios.py --label baseline         # results/baseline_report.md 생성
python -m unittest discover -s tests -v           # 10개 통과
```
Python 3.12 에서 확인했고 외부 패키지는 필요 없다. `python` 이 "Python" 한 줄만 찍으면 `py -3.12` 로 바꿔 실행한다.

## 미리 알아둘 것 (정직하게)

- **지금까지 나온 수치는 모두 참고용이다.** 기본 실행(mock LLM)은 작성자가 만든 규칙으로 동작해서 하네스가 맞게 돌아가는지만 보여 준다.
  실제 LLM 은 연구실 Ollama `qwen2.5:7b` 로 1회만 돌렸고, 그 모델이 도구를 제대로 안 불러서 BLOCKED/FAIL 이 많다. 이것도 취약성 수치가 아니다.
- GPT 등 도구 호출이 안정적인 모델로는 아직 돌리지 못했다.
- 시나리오 A16~A23 은 Udemy 코스의 강의 제목과 설명문을 근거로 추가했다. A17, A20 은 근접 매핑이다.
- 점검 대상은 이 폴더의 코드와 트레이스뿐이다. 가짜 데이터로 만든 로컬 교육용 앱이며 외부 서버로 시나리오를 보내지 않는다.
